## 1. 场景定位

客户有 **多个施工项目**。安全隐患巡检目前用 **Excel** 管理，**跨项目没有统一库**，无法自动预警，也无法自动生成整改报告。

本场景要解决的核心断点是：

> **隐患还停在各项目自己的 Excel 里：没有统一库，没有系统录入入口，更谈不上自动预警和整改报告。**

要建设的是一条完整链，而不是只做看板：

1. **数据上报**：补录入入口（自研页面，或简道云 / fireport 等低代码），写入数据库；
2. **AI 从数据库抓取**，做自动化预警、综合看板、自动整改报告、智能问答。

AI 的价值建立在「先有统一库」之上：没有上报和入库，预警/看板/报告/问答都没有数据源。

## 2. 场景背景（现状）

### 2.1 隐患台账侧

- 多个施工项目的安全隐患巡检，通过 **Excel** 管理。
- **跨项目无统一库**，各项目台账互不相通。
- 整改超期靠人工跟踪；无法自动预警。
- 无法自动生成整改报告；月报仍需人工统计（场景口述估约 **3 天**）。
- 跨项目安全态势无法横向对比。

### 2.2 专项检查侧（场景口述，纪要未改）

本场景同时覆盖以下专项，统一纳入监测与预警：

| 专项领域 | 说明 |
|---|---|
| 防尘 | 扬尘、粉尘等专项检查隐患 |
| 高温 | 高温作业、防暑降温等专项检查隐患 |
| 消防 | 消防设施、通道、用电等专项检查隐患 |
| 防汛 | 汛期排水、边坡、物资等专项检查隐患 |
| 复工复产 | 停工后复工复产条件核查隐患 |
| 日常排查 | 口述未单列，与专项进入同一跟踪闭环 |

### 2.3 录入与数据（纪要澄清，覆盖此前「已有报送系统」的假设）

**目前无系统录入入口。**

需要先解决上报，再让 AI 用数，路径为：

```
现场巡检 → 录入（自研页 或 低代码填报）→ 写入数据库 → AI 从数据库抓取 → 预警 / 看板 / 报告 / 问答
```

录入实现（纪要并列，未拍板用哪一种）：

| 路径 | 说明 |
|---|---|
| A. 自研录入页面 | 在本系统开发「安全隐患排查上报」 |
| B. 低代码填报 | 简道云、fireport 等，填报后数据进库，AI 再抓取 |

字段策略（纪要明确）：

- **隐患填报字段可能随项目变化**（各施工项目检查表不完全一样）。
- **项目信息表相对固定**（项目名称、负责人、工期等主数据稳定，作为跨项目统一库的锚点）。

仍依赖人工的环节：

- 各项目 Excel 分头登记，无统一库
- 整改超期跟踪与预警
- 整改报告 / 月报汇总
- 领导临时问数

## 4. 能力需求

### 4.1 数据上报（纪要新增，且是后续 AI 的前提）

- 提供系统录入能力，替代各项目 Excel。
- 实现方式二选一或组合： **自研「安全隐患排查上报」页面**，或 **简道云 / fireport 等低代码填报**。
- 数据写入数据库，形成 **跨项目统一库**。
- 项目信息走相对固定的项目主数据表；隐患明细字段允许按项目差异扩展。
- AI **不直接读 Excel**，从数据库抓取后做预警、看板、报告、问答。

### 4.2 自动化预警推送

基于库内数据，按整改时限自动跟踪：

1. **临期提醒**：到期前向整改责任人推送。
2. **逾期逐级升级**：逾期后推送项目安全负责人，再升集团分管领导。
3. **重大隐患即时预警**：不按普通时限等待，填报后即时推送。

> 临期天数、升级间隔口述未给。Demo 框架页只展示预警区，规则口头讲即可。

### 4.3 综合业务看板

维度：项目、隐患类型（含专项）、整改完成率。

下钻（场景口述）：

```
集团总览 → 项目 → 具体隐患条目
```

Demo 阶段：看板区域能看清「有预警、有对比」即可，不纠结下钻交互细节。

### 4.4 自动报表生成

- 自动生成安全隐患排查 **整改报告**（纪要） / **按月排查整改报告**（场景口述）。
- 月报内容（口述）：隐患数量趋势、整改完成率、高发问题分析、各项目排名。
- 替代人工统计约 3 天。

### 4.5 智能问答

典型问法：

- 「本月某项目新增隐患多少条」
- 「哪些项目整改完成率最低」
- 「消防类隐患占比多少」

Demo 阶段：页面留问答入口或示意区，具体问答口头讲。

## 5. 典型业务流程

```
巡检发现隐患
  → 通过上报入口填报（自研页 或 简道云/fireport）
  → 写入数据库（项目主数据固定，隐患字段可按项目扩展）
  → 设定整改责任人和时限
  → AI 从数据库抓取，按整改时限跟踪提醒（临期 / 逾期升级 / 重大即时）
  → 整改完成后录入闭环
  → 看板和整改报告自动生成
  → 领导查看态势（可问答）
```

| 步骤 | 系统/角色 | 动作 |
|---|---|---|
| 1 | 巡检 / 项目现场 | 发现隐患 |
| 2 | 填报人 | 在上报入口（自研或低代码）填报并入库 |
| 3 | 填报人 / 安全员 | 设定整改责任人、整改时限 |
| 4 | AI | 从数据库抓取；临期/逾期升级/重大即时预警 |
| 5 | 整改责任人 | 整改完成后录入闭环 |
| 6 | AI | 更新看板；生成整改报告 / 月报 |
| 7 | 集团领导 | 看态势、口头可问数 |

## 9. 约束与边界

- **先有上报和统一库，再有 AI。** 没有录入入口，不单独做无数据源的看板。
- 录入可以自研，也可以低代码（简道云 / fireport）；AI 侧统一从数据库抓取。
- 项目信息表相对固定；隐患填报字段允许随项目变化。
- 专项检查纳入同一套监测预警。
- Demo 以框架和投资分析讲解为主，不把本场景做成细功能产品演示。
- 正式环境再定：临期天数、升级间隔、重大判定、低代码选型、消息通道。
