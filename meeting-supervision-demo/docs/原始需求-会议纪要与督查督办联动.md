## 1. 场景定位

集团重要会议纪要已通过 **OA 审批发布**，并抄送相关人员；集团亦已建成 **督查督办信息化系统**，具备线上报送与状态管理能力。

本场景要解决的核心断点是：

> **会议决策（纪要）与执行跟踪（督查督办）之间未打通。**  
> 纪要要点缺乏结构化提炼，重点工作需人工二次录入督办系统；超期预警与督查周报仍依赖人工。

AI 的价值不在于再建一套督办系统，而在于：

1. 从已发布纪要中自动提取要点与任务；
2. 自动转入现有督查督办系统；
3. 基于已有督办数据做提醒、牌态、看板、周报与问答。

## 2. 场景背景（现状）

### 2.1 会议纪要侧

- 集团重要会议纪要主要通过 **OA 系统审批发布**。
- 发布后以 **抄送** 方式同步给相关人员。
- **接收人员由发起人手工选择**。
- 纪要关键信息容易 **淹没在大量 OA 消息中**。
- **缺乏对纪要要点的结构化提炼**（核心决议、工作任务、责任领导、完成时限等需人工逐篇阅读）。

### 2.2 督查督办侧

- 纪要中形成的 **重点工作部署和任务安排**，往往需 **人工二次录入** 督查督办系统，才能进入跟踪流程。
- **会议决策与执行跟踪之间存在断点**。

### 2.3 已建设能力（必须复用，而非推倒重来）

集团已建设督查督办信息化系统，已完成：

- 线上化数据报送
- 状态管理

系统已覆盖字段/信息包括：

| 信息项 | 说明 |
|---|---|
| 督办类型 | 事项分类 |
| 事项名称 | 督办标题 |
| 任务分解 | 事项拆解 / 时间节点 |
| 本周进展 | 进展填报 |
| 办结时限 | 截止日期 |
| 分管领导 | 升级与阅知对象 |
| 责任单位 | 承办主体 |
| 红黄绿牌状态 | 督办态势标识 |

仍依赖人工的环节：

- **超期预警** 依赖人工关注
- **督查周报** 需人工汇总

## 3. 痛点归纳

| 编号 | 痛点 | 表现 |
|---|---|---|
| P1 | 纪要信息淹没 | OA 全员/大范围抄送，关键决议与任务被消息淹没 |
| P2 | 要点无结构化 | 需人工逐篇阅读纪要，提炼决议、任务、责任人、时限 |
| P3 | 决策—执行断点 | 纪要任务需手工二次录入督查督办，才能进入跟踪 |
| P4 | 知会不准 | 接收人由发起人手工选择，易漏推或过度抄送 |
| P5 | 预警靠人盯 | 临期、逾期无法按办结时限自动监测与升级 |
| P6 | 周报耗时 | 督查周报需人工逐项收集汇总（业务侧估约 2 小时） |
| P7 | 态势不直观 | 需逐项查询，缺少按类型/单位/牌态的总览看板 |
| P8 | 查询成本高 | 领导/办公室难以用自然语言快速问「某会部署了什么」「哪些超期」 |

## 4. AI 应用方式（能力需求）

### 4.1 信息智能提取

- 从 **会议纪要文档** 中自动提取：
  - 核心决议
  - 工作任务
  - 责任领导
  - 完成时限
  - 以及其他关键要点
- 生成 **结构化摘要**
- 替代人工逐篇阅读提炼

### 4.2 任务自动转入督查督办

- 将提炼出的工作任务 **自动生成督查督办事项**
- **转入现有督查督办系统**
- 打通闭环：**会议决策 → 任务分解 → 执行跟踪**
- **消除人工二次录入环节**

### 4.3 自动化提醒与推送

包含三层：

1. **纪要精准推送**  
   根据纪要内容智能匹配需要知晓的相关人员，**精准推送而非全员抄送**。

2. **临期提醒**  
   基于督查督办系统已有数据，按 **办结时限** 自动监测任务进度；临期前向 **负责人** 推送提醒。

3. **逾期升级 + 牌态**  
   逾期后自动升级推送至 **分管领导**；并 **自动评定红黄绿牌状态**。

### 4.4 综合业务看板

- 建设 **督办事项总览看板**
- 可按以下维度展示：
  - 督办类型
  - 责任单位
  - 红黄绿牌状态
- **关联纪要来源**
- 一目了然掌握整体督办态势

### 4.5 自动报表生成

- **每周自动汇总** 各督办事项进展
- 生成 **督查周报** 并推送至集团领导
- 替代人工逐项收集和汇总

### 4.6 智能问答

支持自然语言查询，典型问法包括：

- 「某次会议部署了哪些任务」
- 「本月哪些督办事项超期了」
- 「某事项最新进展如何」

## 5. 典型业务流程

```
会议结束
  → OA 审批发布纪要
  → AI 提取关键要点并生成摘要
  → 提炼任务自动转入督查督办系统
  → 按办结时限自动监测进度并评定红黄绿牌
  → 精准推送至相关人员及责任人
  → 每周自动生成督查周报
  → 领导查看看板决策
```

流程说明：

| 步骤 | 系统/角色 | 动作 |
|---|---|---|
| 1 | 会议组织 / 办公室 | 会议结束，形成纪要稿 |
| 2 | OA | 审批发布纪要（现有能力，保持） |
| 3 | AI | 提取决议/任务/责任领导/时限，生成结构化摘要 |
| 4 | AI → 督查督办 | 任务自动生成事项并转入（现有系统承接跟踪） |
| 5 | 督查督办 + AI | 按办结时限监测；自动红黄绿牌 |
| 6 | 消息/OA/待办 | 精准推送给知会人、责任人；逾期升级分管领导 |
| 7 | AI | 每周生成督查周报推送集团领导 |
| 8 | 领导 | 看总览看板 + 可问答，辅助决策 |

## 9. 约束与边界（从原始表述抽出）

- Demo / 一期建设 **不替代** 客户已有督查督办系统，只做衔接与智能增强。
- 督办过程数据（报送、状态）以现有系统为准。
- 超期预警、牌态、周报应 **基于督查督办已有数据** 计算，而不是另建一套台账。
- 正式环境需对接：OA（纪要发布）、督查督办（事项写入与状态回读）、消息通道（精准推送/升级）。
- 原始需求未要求移动端；当前 Demo 以 PC 为主，与此一致。
